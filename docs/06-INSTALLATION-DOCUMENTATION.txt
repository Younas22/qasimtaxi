========================================
INSTALLATION & DOCUMENTATION
LimoSchedule — Automated Limo Booking System
========================================

Audience: a developer installing this codebase on a fresh server for the first time.
Every command and requirement below is drawn directly from this project's own
composer.json, config files, and migrations — not generic Laravel boilerplate.


## 1. System Requirements

* **PHP 8.2 or newer** (developed/tested against 8.2.12), with these extensions:
  `gd` (required — used to auto-resize uploaded hero images), `pdo_mysql`, `mbstring`,
  `openssl`, `tokenizer`, `xml`, `ctype`, `json`, `bcmath`, `fileinfo`.
* **MySQL or MariaDB** (the project uses Laravel's `mysql` driver; no SQLite/Postgres
  path is configured, though Laravel itself supports them).
* **Composer 2.x**
* **Node.js + npm** — required once, to build the frontend assets
  (`@tailwindcss/vite` ^4.0, Vite ^7.0). Not required at runtime once `public/build/`
  exists on the server.
* **Apache or Nginx**, document root at the project's `/public` directory.
* **SSL/HTTPS** — required in production for browser push notifications (Service
  Workers/Push API refuse to register over plain HTTP outside `localhost`) and
  strongly recommended for Stripe/PayPal checkout and login pages generally.
* No specific disk-space minimum is declared in the codebase; plan for uploaded images/
  vehicle photos/blog images plus database backup files under `public/uploads/`.

## 2. Local Installation

The project ships a Composer convenience script that runs most of the below in one
command:

```
composer setup
```

which internally runs: `composer install` → copy `.env.example` to `.env` →
`php artisan key:generate` → `php artisan migrate --force` → `npm install` →
`npm run build`.

Doing it step-by-step (equivalent, useful when something needs to be inspected between
steps):

```
1.  git clone <repository>   (or extract the delivered source archive)
2.  cd limoschedule_software
3.  composer install
4.  cp .env.example .env
5.  php artisan key:generate
6.  # Edit .env — set DB_* credentials at minimum (see Section 4 below)
7.  # Create the database itself (see Section 3)
8.  php artisan migrate
9.  php artisan db:seed          # optional but strongly recommended — see Section 3
10. npm install
11. npm run build
12. php artisan serve            # or point Apache/Nginx at /public — see Section 7
```

**Note:** `composer setup` does **not** run `php artisan db:seed` — seeding is a
deliberate, separate step (Section 3) because it also creates the first admin login and
a full demo dataset.

## 3. Database Installation

This project uses **Laravel migrations exclusively** — there is no `.sql` dump to
import.

```
1. Create an empty database (e.g. via phpMyAdmin, or:
   mysql -u root -p -e "CREATE DATABASE limoschedule CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;")
2. Set DB_DATABASE/DB_USERNAME/DB_PASSWORD in .env to match.
3. php artisan migrate
4. php artisan db:seed
```

**What seeding gives you** — the 23 seeders run by `DatabaseSeeder` populate a
genuinely complete, working demo site in one command: site Settings, Languages,
Translations, Currencies, Payment Gateway rows (inactive until you add real keys),
Notification Settings, Vehicle Categories + Pricing Rules, Popular Routes, a Coupon, a
Promotion, sample Vehicles, sample Drivers, all CMS Pages (home/about/services/service
pages/legal pages), a Blog category + posts, Locations (countries/states/cities/
airports), the full Permission/Role set, **the first Admin account**, and demo
bookings/customers for realistic testing.

You can re-run an individual seeder later with, e.g.:
```
php artisan db:seed --class=VehicleCategorySeeder
```

## 4. Environment Configuration

Minimum `.env` values to set for a working install (never commit real secret values —
this list is variable **names** and what each controls):

```
APP_NAME="Your Company"
APP_ENV=production
APP_KEY=                     # generated by `php artisan key:generate` — leave blank until then
APP_DEBUG=false              # true only in local development
APP_URL=https://yourdomain.com

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=
DB_USERNAME=
DB_PASSWORD=

SESSION_DRIVER=database
CACHE_STORE=database
QUEUE_CONNECTION=sync        # or `database` if you'd rather run push sends via a worker

MAIL_MAILER=log              # switch to `smtp` (or configure via the admin Email Settings UI) once ready
MAIL_HOST=
MAIL_PORT=
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM_ADDRESS=
MAIL_FROM_NAME="${APP_NAME}"

GOOGLE_MAPS_API_KEY=         # can also be entered later via Admin → System Tools → Integrations

VAPID_PUBLIC_KEY=            # required for browser push — see Section "Push Notification Setup" below
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:admin@yourdomain.com
```

Everything else a client will actually want to change day-to-day — company name, logo,
contact info, theme colors, SEO defaults, Stripe/PayPal keys, tax rate, business hours,
social links, and more — is **database-backed and edited from the Admin Panel**, not
`.env`. See 04-ADMIN-PANEL-FEATURES.txt, "Dynamic Admin-Controlled Features," for the
full list.

## 5. Storage Configuration

**`php artisan storage:link` is NOT required.** Every upload in this codebase (Settings
logos/favicon, page-section images, vehicle photos, blog images, push-notification
sound files, database backup files) is written directly to `public/uploads/...` via
`UploadedFile::move()`, bypassing Laravel's `storage/app/public` + symlink pattern
entirely. Just make sure `public/uploads/` (it will be created automatically on first
upload if missing) is writable by the web server user.

## 6. Permissions

Standard Laravel folder permissions apply:
```
chmod -R 775 storage bootstrap/cache
```
Additionally, since uploads land in `public/uploads/`, ensure that directory (created
on demand) is writable by the web server user as well.

## 7. Web Server Configuration

Point the document root at the project's **`/public`** directory — never at the project
root. Example Nginx server block:

```nginx
server {
    listen 80;
    server_name yourdomain.com;
    root /var/www/limoschedule_software/public;

    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_index index.php;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
```

For Apache, the project's `public/.htaccess` (Laravel's default) handles URL rewriting
as long as `mod_rewrite` is enabled and `AllowOverride All` is set for the `/public`
directory.

## 8. SSL / HTTPS

**Required for:**
* Browser push notifications (Service Worker + Push API registration fails outside
  `localhost` without HTTPS).
* Real Stripe/PayPal checkout flows in production (both providers require it).

**Recommended for everything else** — login pages, the customer/driver/admin panels,
and any page collecting personal data.

## 9. Queue Configuration

Only one queued job exists in the app: `SendPushNotificationJob`. Two supported setups:
* **`QUEUE_CONNECTION=sync`** (the project's current running default) — push sends
  happen inline during the request; no worker process is needed. Simplest option for
  small deployments.
* **`QUEUE_CONNECTION=database`** — offloads push sending to a worker:
  ```
  php artisan queue:table   # only if the jobs table isn't already migrated (it is, by default)
  php artisan queue:work --tries=3
  ```
  Run the worker under Supervisor (or a systemd service) so it restarts automatically;
  a minimal Supervisor program block:
  ```ini
  [program:limoschedule-worker]
  command=php /var/www/limoschedule_software/artisan queue:work --tries=3 --timeout=90
  autostart=true
  autorestart=true
  user=www-data
  numprocs=1
  ```

## 10. Cron Jobs

**None required.** This codebase has no scheduled tasks (`routes/console.php` is
unmodified from the Laravel default; no `app/Console/Commands` exist). There is no
`php artisan schedule:run` cron entry to configure.

## 11. Email Configuration

Two layers exist:
* `.env`'s `MAIL_*` variables are the framework-level fallback/default.
* **Admin → Settings → Email Settings** provides a database-backed SMTP configuration
  UI, so a client can change their outgoing mail provider without touching the server.
Set `MAIL_MAILER=log` only for local development — mail is written to the Laravel log
and never actually delivered in that mode.

## 12. Payment Gateway Configuration

Both gateways are configured entirely from **Admin → Settings → Payment Gateways** —
no `.env` editing needed:
* **Stripe:** enter the Publishable Key + Secret Key for Sandbox and/or Live mode,
  choose the active mode, and toggle the gateway on.
* **PayPal:** enter the Client ID + Client Secret for Sandbox and/or Live mode, choose
  the active mode, and toggle the gateway on.
A gateway only becomes "ready" (and therefore capable of gating booking confirmation on
real payment) once its active-mode credentials are filled in and it is toggled on.

## 13. Maps API Configuration

1. In Google Cloud Console, enable: **Geocoding API**, **Distance Matrix API**, **Maps
   JavaScript API**, and **Places API**.
2. Create an API key; restrict it by HTTP referrer (your domain) for safety.
3. Enter it either in `.env` as `GOOGLE_MAPS_API_KEY`, or — simpler — via
   **Admin → System Tools → Integrations**, which also offers a **live "Test
   Connection"** button that calls Google's Geocoding API and reports back exactly why
   a key fails (invalid, restricted, API not enabled, over quota, etc.) before you rely
   on it.

## 14. Push Notification Setup (VAPID)

Browser push requires a one-time VAPID key pair, generated locally with the package
already installed via Composer:

```
php -r "require 'vendor/autoload.php'; print_r(Minishlink\WebPush\VAPID::createVapidKeys());"
```

Copy the resulting `publicKey`/`privateKey` into `.env`:
```
VAPID_PUBLIC_KEY=<publicKey>
VAPID_PRIVATE_KEY=<privateKey>
VAPID_SUBJECT=mailto:admin@yourdomain.com
```

Then, as an admin, visit **Admin → Settings → Notifications**, turn on the master
**Enable Browser Push Notifications** switch, enable the roles/events you want, and use
the **Send Test** button to confirm delivery to your own logged-in browser.

**Windows development note only:** if VAPID signing throws an OpenSSL
"configuration file routines::no such file" error (a known Windows PHP/OpenSSL quirk,
not a production Linux issue), set `WEBPUSH_OPENSSL_CONF` in `.env` to the full path of
a valid `openssl.cnf` on that machine.

## 15. Admin Account

The first admin account is created by the seeder, not by a setup wizard:
```
php artisan db:seed --class=AdminSeeder
```
This creates `admin@limoschedule.test` / `password` (assigned the Super Admin role) —
**change this password immediately after first login** via Admin → Profile. Additional
admins are created from **Admin → Settings → Roles & Permissions → (assign a role) →
Admins**, each with their own email/password and a chosen role's permission set.

## 16. Customer & Driver Accounts

* **Customers** self-register via the public `/register` page, or an admin can create
  one directly from **Admin → Customers → Add Customer**. A guest can also complete a
  full booking with no account at all — a `Customer` record is resolved/created
  transparently from the guest's contact details.
* **Drivers do not self-register.** Every driver account is created by an admin, from
  **Admin → Drivers → Add Driver** (name, contact info, license/passport/ID numbers,
  commission rate, assigned vehicle) — there is no public driver sign-up form. Drivers
  log in at a **separate URL**, `/driver/login`, not the shared `/login` page used by
  customers and admins.

## 17. Production Deployment Checklist

* [ ] `APP_ENV=production`, `APP_DEBUG=false`
* [ ] Real `APP_URL` (matching your actual domain, including `https://`)
* [ ] Production database credentials, migrated (`php artisan migrate --force`)
* [ ] `php artisan config:cache`, `php artisan route:cache`, `php artisan view:cache`
* [ ] `npm run build` executed and `public/build/` deployed
* [ ] SSL certificate installed and enforced (redirect HTTP → HTTPS)
* [ ] Real SMTP credentials set (via Admin → Email Settings or `.env`) — confirm a test
  email actually arrives, not just logs
* [ ] Stripe/PayPal **live** credentials entered and the correct mode selected, with a
  real end-to-end test payment before launch
* [ ] Google Maps API key set, "Test Connection" passing, and billing enabled on that
  Google Cloud project
* [ ] VAPID keys generated and set; push "Send Test" confirmed working over HTTPS
* [ ] `storage/` and `bootstrap/cache/` writable by the web server user
* [ ] `.env` itself is **not** web-accessible (default `.htaccess`/Nginx rules already
  block dot-files — verify on your specific server)
* [ ] First admin password changed from the seeded default
* [ ] Full booking workflow tested end-to-end: guest booking → payment → admin
  confirmation/driver assignment → driver start/complete → customer invoice/PDF
* [ ] Backup schedule decided (Admin → System Tools → Backup can create one on demand;
  there is no automatic/cron-scheduled backup — see Section 20)

## 18. Troubleshooting

* **500 error, blank page:** set `APP_DEBUG=true` temporarily (development/staging
  only) and check `storage/logs/laravel.log`, or use Admin → System Tools → Error Logs
  once you can log in.
* **"Missing APP_KEY":** run `php artisan key:generate`.
* **Database connection error:** confirm `DB_*` values in `.env` and that the database
  user has privileges on that database; confirm the DB server is actually reachable
  from the app server (firewall/port).
* **Composer install fails on PHP version:** confirm PHP 8.2+ is the CLI version
  Composer is using (`php -v`); a server with an older default PHP behind a newer
  FPM pool is a common false alarm.
* **npm build fails:** confirm Node.js is installed and `npm install` completed
  without errors before running `npm run build`; delete `node_modules` and retry if a
  lockfile mismatch is suspected.
* **Uploaded images don't show / 404 on upload paths:** this project does not use
  `storage:link` (see Section 5) — check that `public/uploads/` exists and is writable,
  not that a symlink is missing.
* **Emails not sending:** `MAIL_MAILER=log` silently "succeeds" by writing to the log
  instead of sending — check `storage/logs/laravel.log` for the rendered email, and
  confirm real SMTP credentials are set (Admin → Email Settings) if you expected actual
  delivery.
* **Payments not working:** confirm the gateway is toggled **active** and the
  **correct mode** (sandbox vs. live) matches the credentials entered — a live key pair
  saved while "Sandbox" mode is selected (or vice versa) will fail silently from the
  customer's perspective.
* **Maps/Autocomplete not loading:** use the Integrations page's "Test Connection" to
  get Google's actual error message (invalid key, API not enabled, referrer
  restriction, billing not enabled) rather than guessing.
* **Push notifications not arriving:** confirm the site is served over HTTPS (or
  `localhost` for local testing), that VAPID keys are set, that the master switch and
  the relevant role/event switches are all on, and use "Send Test" to isolate whether
  the problem is delivery (server→browser) or the toggle configuration. A closed
  browser will still show the OS's own default notification sound even with a custom
  sound uploaded — that's expected, not a bug.
* **Queue/jobs "not running":** if `QUEUE_CONNECTION=sync`, there is nothing to run —
  jobs execute inline. If you've switched to `database`, confirm a `queue:work` process
  is actually running (see Section 9) and check Admin → System Tools for failed jobs.
* **Cron "not running":** there is no cron-dependent functionality in this codebase to
  troubleshoot (see Section 10).

## 19. Updating the Application

There is no built-in "check for updates" or auto-updater. A safe manual update:
```
1. Back up the database (Admin → System Tools → Backup, or a manual mysqldump) and the
   public/uploads/ directory.
2. Pull/apply the new source code (git pull, or replace files, preserving your .env
   and public/uploads/).
3. composer install --no-dev --optimize-autoloader
4. php artisan migrate --force
5. npm install && npm run build
6. php artisan config:cache && php artisan route:cache && php artisan view:cache
7. php artisan queue:restart   (if using a queue worker)
```
Admin → System Tools also exposes **Run Migrations** and **Composer Update** directly
from the browser, for environments without SSH access — use with the same caution as
any production schema/dependency change.

## 20. Backup Recommendations

Back up, on a regular schedule:
* **The database** — Admin → System Tools → Backup can create a downloadable SQL dump
  on demand (a custom exporter, not `mysqldump`-dependent), but **this is manual, not
  automatic** — there is no cron-scheduled backup in this codebase. Wire it into your
  own server-level cron/backup tooling (e.g. a nightly `mysqldump` + off-site copy) for
  real production safety.
* **`public/uploads/`** — every logo, vehicle photo, page image, blog image, and
  push-notification sound file lives here; it is not part of the database backup.
* **`.env`** — holds your database credentials, VAPID keys, and app key; losing it
  without a copy means regenerating VAPID keys (re-subscribing every push user) and
  reconfiguring mail/Maps settings from scratch.
* Treat a restore as destructive — the in-app **Restore Backup** tool (and the
  separate **Drop All Tables** tool) both operate directly on your live database with
  no undo.
